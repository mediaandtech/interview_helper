# 발표 연습 도구 설계 문서

작성일: 2026-11-13
상태: 검토 반영 완료, 팀 승인 대기

> 표기: **[팀 결정]** = 대화에서 팀이 정한 것, **[설계자 판단]** = 문서 작성 중 정한 것(바꿔도 됨), **[구현자 재량]** = 만드는 사람이 정하면 되는 것.

## 1. 무엇을, 왜 만드나

웹캠과 마이크만으로 발표자의 **시선(정면 응시), 말하기 속도, 목소리 크기, 음성 높낮이 변화, 발표 시간**을 실시간으로 보여 주고, 발표가 끝나면 종합 피드백 리포트를 보여 주는 웹 기반 발표 연습 도구.

**필요성 [팀 결정]**
- 독학으로는 말하기 속도·성량·시선 같은 비언어적 습관을 객관적으로 파악하기 어렵다.
- 스피치 학원·유료 분석 서비스는 비용 부담이 커 대학생·취준생이 상시 이용하기 어렵다.
- 웹캠과 마이크만으로 실시간 지표와 리포트를 제공해 별도 비용 없이 발표 완성도를 높인다.

**맥락 [팀 결정]**
- 숭실대 디지털미디어학과 Media&Tech 수업 **팀 기말 과제**.
- 약 **2주 후(2026-11-27 전후)** 교수님·학생들 앞에서 **라이브 시연**. 팀원이 노트북 앞에 앉아 카메라를 보며 실제로 발표하고, 화면 지표가 반응하는 모습을 프로젝터로 보여 준다.
- 시연 환경: **Mac 노트북(MacBook 내장 카메라, 화면 위쪽 가운데) + Chrome + 인터넷 사용 가능**. [팀 결정]
- 프로젝터 연결 방식(복제/확장)은 미정 → 1280×720까지 낮춰도 레이아웃이 깨지지 않게 만든다. [설계자 판단]
- **구현은 Claude가 전부 맡는다.** 팀원은 테스트·임계값 조정·시연 리허설을 한다. [팀 결정]
- 교수님은 특정 라이브러리 사용 여부를 평가하지 않는다. → MediaPipe, Web Audio 직접 사용 확정. [팀 결정]

**성공 기준**
- 시연 5분 동안 멈추거나 오류 없이 설정 → 연습 → 리포트 흐름이 끝까지 이어진다.
- 발표자가 고개를 돌리거나 목소리를 낮추면 관객이 1~2초 안에 패널 색 변화를 보고 알아챈다.
- 리포트가 "언제, 무엇을, 어떻게 고치라"는 구체적인 문장을 보여 준다.

## 2. 목표 / 비목표 / 반(反)목표

**목표**
- 6개 기능: 실시간 시선 분석, 말하기 속도, 목소리 크기, 높낮이 변화, 발표 시간 설정·제한, 종료 후 종합 리포트. [팀 결정]
- **시선 분석이 주인공.** 6개 중 하나만 완벽해야 한다면 시선이다. 개발 시간도 시선에 가장 많이 배정한다. [팀 결정]
- 설정 → 연습 → 리포트가 자연스럽게 이어지는 흐름. [팀 결정]

**비목표 (이번에 안 함)** [설계자 판단]
- 모바일·태블릿 지원, Safari·Firefox 지원 (Chrome 데스크톱만)
- 회원가입, 클라우드 저장, 여러 사람 동시 분석
- 영상·음성 녹화 파일 저장
- LLM 같은 생성형 AI로 피드백 문장 만들기 (규칙 기반 문장으로 충분)
- 서 있는 발표자를 멀리서 분석하기 (노트북 앞에 앉은 상태 전제)

**반목표 (돌아가더라도 이러면 실패)**
- 시연 중 멈춤·권한 오류·빈 화면. 안정성이 기능 수보다 우선한다.
- 패널이 숨 쉴 때마다 빨강/초록으로 깜빡여 오히려 발표를 방해하는 것 (시각적 노이즈).
- 지표를 보려고 눈을 돌릴 때마다 시선 점수가 깎이는 구조.
- 설정이 복잡해 연습 시작까지 30초 넘게 걸리는 것.
- 우리가 만든 서버로 영상·음성을 보내는 것. (Chrome 음성 인식이 구글로 음성을 보내는 것은 허용, 설정 화면에 한 줄로 안내.)

## 3. 제약

- **p5.js 사용**, **서버 없이 프론트엔드만** (정적 파일). [팀 결정]
- **UI는 그라파나와 비슷하게**: 어두운 배경, 얇은 테두리 패널, 작은 대문자 패널 제목, 큰 숫자, 초록/주황/빨강 상태색. [팀 결정]
- 개발 기간 약 2주. 구현은 Claude 단독이지만, 팀원이 나중에 읽고 고칠 수 있게 기능 단위로 파일을 나눈다. [설계자 판단]
- 빌드 도구 없이 동작 (CDN `<script>` 또는 ES 모듈). 실행은 로컬 정적 서버(`python3 -m http.server` 등) 또는 GitHub Pages 같은 HTTPS 정적 호스팅. `file://`로 열면 카메라·모델 로딩이 불안정하므로 쓰지 않는다. [설계자 판단]
- 시연 안정성을 위해 얼굴 인식 모델 파일(wasm, .task)은 **프로젝트 안에 복사**해 두고 로컬에서 불러온다. 인터넷이 끊겨도 시선·크기·높낮이·시간은 동작해야 한다. [설계자 판단]

## 4. 화면과 흐름

모든 화면 상단에 진행 표시 `① 설정 → ② 연습 → ③ 리포트`. [설계자 판단]

### 4.1 설정 화면 [팀 결정: 제안안 그대로 승인]

"3개만 정하고 바로 시작"을 목표로 한다.

1. **발표 유형** 칩 선택: 수업 발표 / 면접 답변 / 피칭·공모전. 선택하면 아래 기준값 프리셋이 채워진다.
2. **발표 시간**(분:초). 기본 05:00.
3. **준비 확인(보정, 약 10초)**
   - 카메라를 정면으로 보게 하고 그 자세의 고개 각도·눈 방향을 "정면 기준"으로 저장한다(노트북 카메라 위치·각도 차이를 보정).
   - 안내 문장("안녕하세요, 발표를 시작하겠습니다")을 평소 목소리로 읽게 하고 **기준 음량(dB)**과 **기준 음높이(Hz)**를 저장한다. 마이크마다 감도가 달라 절대 dB 기준은 쓰지 않는다.
   - 각 항목 옆에 ✓ 표시. 얼굴이 안 잡히거나 마이크 권한이 없으면 무엇을 하라는 안내 문장을 보여 준다.
- **고급 설정**(기본 접힘): 적정 속도 범위, 크기 허용 범위, 정면 응시 목표 %, 높낮이 변화 기준.
- **연습 시작** 버튼. 보정이 끝나야 활성화.

**프리셋 기본값** [설계자 판단, 실제 테스트 후 조정 필요]

| 유형 | 적정 속도(음절/분) | 정면 응시 목표 |
|---|---|---|
| 수업 발표 | 270 ~ 330 | 80% |
| 면접 답변 | 260 ~ 320 | 85% |
| 피칭·공모전 | 290 ~ 350 | 80% |

### 4.2 실시간 연습 화면 [팀 결정: C안 "그라파나 그리드"]

```
┌──────────────────────── (카메라) ────────────────────────┐
│  ① 설정  ② 연습  ③ 리포트        [● 정면 87%]          [종료] │
│ ┌───────────────────────────────┐ ┌───────────────────┐ │
│ │                               │ │ 속도 (음절/분) 312 │ │
│ │   웹캠 영상 (좌우 반전)        │ ├───────────────────┤ │
│ │   + 얼굴 인식 점 / 시선 방향   │ │ 크기 (기준 대비) │ │
│ │                               │ ├───────────────────┤ │
│ │                               │ │ 높낮이 (10초 그래프)│ │
│ │                               │ ├───────────────────┤ │
│ └───────────────────────────────┘ │ 남은 시간 03:12   │ │
│                                   └───────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

- 왼쪽 약 60%: 웹캠 영상. 그 위에 얼굴 인식 점(얇게, 반투명)과 시선 방향 표시를 겹친다. 시선이 정면이 아니면 영상 테두리도 상태색으로 바뀐다. [설계자 판단]
- **시선 가이드는 화면 위쪽 가운데, 카메라 바로 아래**에 알약 모양 표시("● 정면 87%")로 둔다. 지표를 보러 눈을 돌려도 카메라에서 멀어지지 않게 하기 위해서다. [팀 결정: 세 시안 공통 원칙]
- 오른쪽 패널 4개를 세로로 쌓는다: 속도 / 크기 / 높낮이(최근 10초 흐름 그래프 + "단조/적정" 라벨) / 남은 시간.
- **상태색**: 초록 `#73bf69` 적정, 주황 `#ff9830` 주의, 빨강 `#f2495c` 이탈. 빨강일 때 패널 배경도 살짝 붉게. 패널 왼쪽 굵은 테두리로 상태를 표시한다.
- **깜빡임 방지(히스테리시스)**: 속도·크기·높낮이 패널은 상태가 바뀐 채로 **1초 이상 유지**돼야 색이 바뀐다. 시선 표시는 5.1의 별도 규칙(1.5초/3초)을 따른다. [설계자 판단]
- 프로젝터 시연을 고려해 숫자는 크게(패널 숫자 최소 32px 수준). [설계자 판단]
- 종료: [종료] 버튼 또는 스페이스바/ESC → 리포트로 이동. 시간이 초과돼도 자동 종료하지 않고 계속 측정한다.
- 연습 시작 시 3초 카운트다운. [설계자 판단]

### 4.3 리포트 화면 [팀 결정: 제안안 그대로 승인]

위에서 아래로:
1. **한 줄 결론 + 종합 점수(0~100)**: 가장 잘한 점 1개, 가장 아쉬운 점 1개. 유형, 목표/실제 시간, 날짜.
2. **지표 요약 5칸**: 정면 응시 %, 평균 속도, 크기 이탈 비율, 높낮이 변화(단조/보통/풍부), 시간(목표 대비 ±).
3. **시간 흐름 그래프**: 시선(정면/이탈 구간 띠), 속도, 크기, 높낮이를 **같은 시간축**에 위아래로 쌓는다(그라파나 방식). 이탈 구간을 클릭하거나 마우스를 올리면 그 순간의 설명이 나온다.
4. **다음 연습에서 고칠 것 3가지**: 타임스탬프가 붙은 구체적인 문장. 예) "3:50 이후 목소리가 기준보다 25% 작아졌어요. 결론 부분일수록 크게 말해 보세요." / "1:37에 7초 동안 시선이 아래로 향했어요."
5. **버튼**: 다시 연습(같은 설정 유지) / PDF로 저장(`window.print()` + 인쇄용 CSS).

**선택 기능 (시간이 남으면)**
- "음", "어", "그" 같은 군말 횟수 (음성 인식 텍스트 기반)
- 지난 기록과 비교 (localStorage에 요약만 저장)

## 5. 측정 방식

### 5.1 시선 (최우선)
- 라이브러리: **MediaPipe Face Landmarker** (`@mediapipe/tasks-vision`). 478개 얼굴 점(홍채 포함), 얼굴 변환 행렬(고개 각도), 눈 방향 blendshape(`eyeLookDown/Up/In/Out`)을 한 번에 제공한다. ml5 faceMesh도 대안이지만 고개 각도·눈 방향을 직접 계산해야 해서 제외. [설계자 판단]
- 판정: **고개 방향 + 눈동자 방향 결합** [대화에서 합의한 방향, 세부는 설계자 판단]
  - 보정 때 저장한 정면 기준 대비 고개 yaw ±15°, pitch ±12° 이내 **그리고** 눈 방향 blendshape가 임계값(시작값 0.5) 미만이면 "정면".
  - 얼굴이 안 잡히면 "정면 아님".
- 출력: 순간 상태(정면/아님 + 이탈 방향: 아래·좌·우·위), 누적 정면 응시 %, **3초 이상 연속 이탈 이벤트**(시작 시각, 길이, 방향).
- **지표 확인용 짧은 시선 이동은 봐준다** [설계자 판단]: 1.5초 미만의 짧은 이탈은 정면 응시 %와 점수에서 "정면"으로 처리한다. 오른쪽 패널을 잠깐 확인하는 행동을 벌주지 않기 위해서다(반목표 참고). 기록에는 원래 상태를 남기고, 점수 계산 단계에서 봐준다.
- **반응 속도 2단계** [설계자 판단]: 관객이 1~2초 안에 변화를 보도록 한다.
  - 빠른 표시: 위쪽 시선 알약과 웹캠 테두리는 순간 상태를 따른다. 1.5초 이상 이탈하면 주황, 3초 이상이면 빨강으로 바뀐다. 정면으로 돌아오면 0.5초 뒤 초록이 된다.
  - 느린 표시: 알약 안의 "정면 87%" 숫자는 최근 30초 정면 비율이다(짧은 이탈 봐주기 적용). 목표% 이상이면 초록, 목표보다 15%p 낮은 값까지는 주황, 그 아래는 빨강.
- 처리 속도: 초당 15~30회. 영상 해상도는 640×480으로 고정해 부담을 줄인다.

### 5.2 목소리 크기
- Web Audio `AnalyserNode`로 RMS → dB. 매 프레임 계산. [설계자 판단: p5.sound 대신 Web Audio를 직접 사용. 높낮이 계산과 같은 노드를 공유하기 위해서]
- **말하는 중일 때만 평가** (간단한 음성 구간 감지: 기준 음량보다 크게 낮은 소음 바닥은 "침묵"으로 처리). 쉬는 시간을 "목소리 작음"으로 벌주지 않는다.
- 기준 대비: −6 dB ~ +8 dB 초록, −10 ~ −6 dB 또는 +8 ~ +12 dB 주황, 그 밖은 빨강. [시작값, 테스트 후 조정]
- 표시는 "기준 대비 막대 + 작음/적정/큼" 라벨. 실제 dB 숫자는 보조로만 쓴다.

### 5.3 음성 높낮이 변화
- 음높이(F0) 추정: 자기상관(autocorrelation) 방식으로 직접 구현, 75~400 Hz 범위, 말하는 구간에서만. [설계자 판단]
- 변화량: 최근 10초 유성음 구간 F0를 반음(semitone) 단위로 바꾼 뒤 표준편차를 구한다. 1.5 반음 미만이면 "단조"(주황), 1.5~4 반음이면 "적정"(초록), 4 반음 초과면 "풍부"(초록). [시작값]
- 패널: 최근 10초 F0 흐름 그래프 + 라벨.

### 5.4 말하기 속도 (하이브리드)
- **즉시 추정값**: 음량 포락선(envelope)의 봉우리 수로 음절을 추정한다. 최근 10초 창.
- **보정값**: Chrome Web Speech API(`lang='ko-KR'`, `continuous`, `interimResults`). 인식된 텍스트의 **한글 음절 수**를 시간과 함께 기록한다.
- 화면 표시값 = 즉시 추정값 × 보정 계수. 보정 계수는 최근 30초 동안 "인식 음절 수 / 추정 음절 수"로 계속 갱신한다. 인식이 없으면 1.0을 쓴다.
- 단위: 음절/분. 계산 기준은 경과 시간(쉬는 시간 포함). [설계자 판단]
- Chrome 음성 인식은 일정 시간 뒤 스스로 끝나므로 `onend`에서 자동 재시작한다. 실패하면 추정값만으로 계속 동작한다.
- 리포트의 평균 속도는 음성 인식 기반 값을 우선 쓰고, 없으면 추정값을 쓴다.

### 5.5 발표 시간
- 설정한 시간부터 거꾸로 센다. 남은 1분부터 주황, 0 이후 빨강 + "+0:24" 형식으로 초과 시간을 표시한다.

## 6. 점수와 피드백 규칙 [설계자 판단]

- **기록**: 연습 중 초당 10회 각 지표를 샘플로 배열에 쌓는다(시각, 정면 여부, 이탈 방향, 속도, dB, F0, 말하는 중 여부). 리포트는 이 배열만으로 만든다.
- **종합 점수 가중치**: 시선 35 / 속도 20 / 크기 20 / 시간 15 / 높낮이 10. 각 지표 점수는 "적정 범위 안에 있던 시간 비율"을 기본으로 한다.
- **피드백 문장**: 문제 후보(연속 시선 이탈, 크기 저하 구간, 속도 과속/저속 구간, 단조 구간, 시간 초과)마다 심각도(길이 × 이탈 정도)를 계산해 상위 3개를 문장 템플릿으로 출력한다. 문제가 적으면 칭찬 문장으로 채운다.
- 한 줄 결론 = 점수가 가장 높은 지표 + 가장 낮은 지표.

## 7. 기술 구성

- p5.js 1.x(CDN 버전 고정), **인스턴스 모드**로 여러 캔버스를 쓴다. 웹캠 + 얼굴 점 오버레이, 패널 미니 그래프, 리포트 그래프를 p5로 그린다. 패널 레이아웃과 텍스트는 HTML/CSS로 만든다. [설계자 판단: 그라파나 느낌과 글자 선명도는 DOM이 유리하고, 실시간 그래픽은 p5로 그린다]
- 화면 전환은 한 페이지 안에서 `setup / practice / report` 상태로 처리한다.
- 파일 구조 (팀원이 나눠 맡는 단위) [설계자 판단]
  ```
  index.html
  css/style.css            그라파나 테마 토큰, 패널, 인쇄용 CSS
  js/config.js             모든 임계값·프리셋 (팀원 조정용)
  js/app.js                화면 상태 전환, 설정값 보관
  js/setup.js              설정 화면 + 보정
  js/practice.js           연습 화면, 패널 갱신, 히스테리시스
  js/report.js             리포트 화면, 그래프, PDF
  js/sensors/gaze.js       MediaPipe 시선 판정
  js/sensors/audio.js      마이크, 크기, 음성 구간, 높낮이
  js/sensors/speech.js     Web Speech 인식, 음절 수
  js/analysis/rate.js      속도 하이브리드 계산
  js/analysis/scoring.js   점수, 피드백 문장
  js/recorder.js           샘플 기록
  vendor/mediapipe/        wasm, face_landmarker.task
  ```
- 팀원 역할: 구현 결과를 각자 노트북으로 테스트하고, 실제 발표로 임계값을 맞추고, 시연을 리허설한다.
- 각 설정값(임계값·프리셋)은 `js/config.js` 한 파일에 모아서, 코드를 몰라도 팀원이 숫자만 바꿔 조정할 수 있게 한다. [설계자 판단]
- 권한·오류 처리: 카메라·마이크 거부, 얼굴 미검출, 음성 인식 미지원 등 경우마다 화면에 안내를 띄우고, 가능한 기능만으로 계속 동작한다.
- 개인정보: 영상·음성은 브라우저 밖으로 저장하거나 전송하지 않는다(음성 인식은 예외이며 안내 문구 표시).

## 8. 구현자에게 맡기는 것 [구현자 재량]

- 각 임계값·프리셋 숫자의 최종 조정 (팀원 실제 발표로 테스트하며 맞춘다)

- 테스트 방식 (순수 계산 함수인 점수, F0, 음절 세기, 히스테리시스는 자동 테스트를 권장)
- 배포 방식 (로컬 서버 또는 GitHub Pages)

## 9. 일정 가이드 (약 2주) [설계자 판단]

- 1주차 전반: 뼈대(화면 3개 전환, 테마), 카메라·마이크 연결, 시선 판정 1차
