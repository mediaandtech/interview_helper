# SpeechBoard: 면접 답변을 직접 돌아보는 도구

질문에 답한 뒤 자신의 영상·음성·측정값을 확인하고 메모를 남기는 브라우저 도구입니다. 제3자 평가, AI 답변 평가, 종합 점수, 등급, 자동 칭찬이나 행동 권고를 제공하지 않습니다. 무엇을 바꿀지는 사용자가 직접 판단합니다.

## 개발 환경과 실행

이 프로젝트는 브라우저 JavaScript 앱입니다. **Python 가상환경은 사용하지 않으며, Node.js만으로 실행·테스트할 수 있습니다.** 팀 개발 버전은 **Node.js 24.22.3**으로 고정했으며, `.nvmrc`가 기준 파일입니다. Node.js 22 이상에서도 단위 테스트를 확인했지만 협업 시에는 고정 버전을 사용하세요.

저장소를 clone한 뒤 프로젝트 폴더에서 실행합니다.

```sh
npm ci
npm start
```

Chrome에서 `http://localhost:8081`을 엽니다. macOS/Linux의 nvm 사용자는 설치 전에 `nvm install`, `nvm use`로 버전을 맞춥니다.

Windows에서는 [nvm-windows](https://github.com/nvm-windows/nvm)를 설치한 뒤 PowerShell에서 다음을 실행합니다. 스크립트가 `.nvmrc`를 읽어 같은 버전을 설치·선택하고 실제 적용 여부까지 확인합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\use-node.ps1
npm.cmd ci
npm.cmd run doctor
npm.cmd start
```

`-ExecutionPolicy Bypass`는 위 스크립트를 실행하는 프로세스에만 적용하며 시스템 실행 정책을 변경하지 않습니다. nvm-windows를 사용하지 않는 경우에도 동일한 Node.js 버전을 직접 설치한 뒤 `npm.cmd run doctor`로 확인할 수 있습니다.

포트 변경은 `npm start -- 9000`입니다. macOS·Windows·Linux에서 같은 npm 명령을 사용합니다.

- `npm run doctor`: 현재 Node.js와 `.nvmrc` 버전 일치 확인 (`npm start`와 `npm run dev`도 시작 전에 자동 확인)
- `npm ci`: lock 파일의 동일한 개발 의존성 설치
- `npm start` / `npm run dev`: 캐시 없는 로컬 서버 실행, 별도 빌드 없음
- `npm test`: 단위·회귀 테스트
- `npm run setup:browser`: 브라우저 검증용 Chromium 최초 설치
- `npm run test:browser`: 로컬에서 임시 서버를 자동 실행해 복기·시선·인쇄 검증 (CI에서는 실행하지 않음)

런타임 외부 패키지와 API 키는 필요하지 않습니다. Playwright는 개발 검증에만 사용합니다. 검증 결과는 Git에서 제외되는 `.artifacts/`에 저장합니다. 배포는 정적 파일을 HTTPS로 제공하면 됩니다. `file://` 대신 로컬 서버를 사용하세요.

자세한 설치·검증·PR 절차는 [CONTRIBUTING.md](CONTRIBUTING.md)를 참고하세요. Node.js 버전 정책은 [공식 릴리스 안내](https://nodejs.org/en/about/previous-releases), 브라우저 설치는 [Playwright 안내](https://playwright.dev/docs/browsers)를 기준으로 합니다.

## 사용 흐름

1. **질문과 참고 범위 설정:** 질문, 답변 시간, 속도 및 정면 좌우·위아래 참고 범위를 정합니다. 프리셋은 편집 가능한 초기값이며 면접 성과 기준이 아닙니다.
2. **녹화 선택:** ‘답변을 녹화·녹음하여 직접 다시 보기’를 선택하면 카운트다운이 끝난 뒤 녹화를 시작합니다. 기본값은 녹화 안 함입니다. 카메라 없이 마이크만 있으면 녹음할 수 있습니다.
3. **준비 확인:** 2초간 정면과 주변 소음, 4초간 읽는 목소리를 측정합니다. 장치가 없는 경우 사용 가능한 측정만으로 진행할 수 있습니다.
4. **답변:** 기본적으로 실시간 지표를 숨깁니다. ‘측정값 보기’로 표시할 수 있습니다. 종료 버튼 또는 Esc로 끝냅니다. 설정 시간을 넘겨도 자동 종료하지 않습니다.
5. **직접 복기:** 영상 재생, 그래프 클릭, 키보드로 조작 가능한 시간 슬라이더로 특정 위치를 확인합니다. 위치별 메모와 전체 복기 메모를 남깁니다.
6. **재연습·비교:** 같은 질문으로 준비 확인을 다시 한 뒤 답변합니다. 같은 질문의 이전 실제 답변을 선택해 영상·측정값·메모를 함께 봅니다. 점수 차이나 자동 개선 판단은 표시하지 않습니다.

카운트다운 중 종료하거나 아주 짧게 답변해도 복기 메모를 남길 수 있습니다. 녹화 지원이나 파일 생성이 실패하면 그 이유를 표시하고 측정값·메모는 계속 사용할 수 있습니다.

## 보관과 삭제

- 영상·음성은 외부로 전송하지 않습니다. 외부 음성 인식 서비스도 실행하지 않습니다.
- 실제 답변은 **현재 탭의 메모리에 최근 5개**까지 보관합니다. 여섯 번째 답변을 만들면 가장 오래된 답변과 녹화가 해제됩니다.
- 새로고침하거나 탭을 닫으면 영상·메모·측정값이 사라집니다. 영구 저장소나 서버에는 저장하지 않습니다.
- 필요한 녹화 파일과 측정값·메모 JSON은 각각 다운로드할 수 있습니다. 다운로드한 파일은 사용자가 직접 관리합니다. 현재 버전은 JSON 재가져오기를 제공하지 않습니다.
- ‘이 녹화 삭제’는 현재 답변의 영상·음성만 삭제하고 메모는 유지합니다. ‘보관한 답변·메모 모두 삭제’는 탭 안의 답변 기록을 모두 지웁니다.
- 답변 종료 시 카메라·마이크를 끕니다. 재연습 시 준비 확인을 다시 진행합니다.
- 데모는 실제 답변 비교 기록에 저장하지 않습니다.

## 측정값 해석

- **정면 범위 안:** 얼굴이 검출된 표본 중 설정한 고개 범위와 눈 방향 기준 안에 있는 비율입니다. 실제 면접관과의 눈맞춤이나 면접 실력을 의미하지 않습니다. 얼굴 미검출은 별도 구간으로 표시합니다.
- **속도 추정:** 음량의 봉우리로 음절 수를 추정합니다. 실제 단어·음절을 인식하지 않아 오차가 있을 수 있습니다. 측정 가능한 표본의 평균과 측정 시간을 함께 표시합니다.
- **음량 변화:** 준비 확인 때 측정한 기준 대비 dB 차이입니다. 장치·거리·환경이 달라지면 답변 간 수치를 직접 비교하기 어렵습니다.
- **음높이 변화:** 발화로 추정된 구간에서 검출한 음높이의 반음 표준편차입니다. 자신감이나 전달력을 판정하지 않습니다.
- **시간·공백:** 실제 경과 시간과 10Hz 기록 표본에 해당하는 시간을 구분해 표시합니다. 백그라운드 탭이나 느린 기기에서는 표본이 누락될 수 있습니다. 공백을 가로질러 관찰 구간을 합치지 않습니다.

그래프와 참고 범위 구간 목록은 재생 위치를 찾는 데 사용합니다. 범위 밖이라는 이유만으로 문제가 있다고 판단하지 않습니다.

## 데모와 장치 점검

- `?demo=1`: 카메라·마이크 없이 가상 측정값으로 연습과 복기를 체험합니다. 녹화 파일은 생성하지 않습니다.
- `?debug=1`: 센서 원시값 표시.
- 설정 화면의 ‘시선 인식 테스트’: 안내된 방향과 감지값이 일치하는지 장치를 점검합니다. 이 화면의 일치율은 면접 수행 평가가 아닙니다.

## 디자인

- UI는 **Basecoat UI 1.1.0**(shadcn/ui 디자인 언어, React 없음)의 다크 테마를 씁니다. 라이브러리 CSS는 `vendor/basecoat/`에 있어 인터넷 없이 동작합니다.
- 토큰은 `css/tokens.css`, 화면 배치는 `css/app.css`, 재사용 부품은 `js/ui/components.js`입니다.
- 기준 문서: `design-system/speechboard/MASTER.md` · 살아 있는 예시: `styleguide.html` (서버 실행 후 `/styleguide.html`)

## 구조

- `js/analysis/review.js`: 점수 없는 관찰 요약, 공백을 분리한 구간, 시각 기반 표본 조회
- `js/media-recorder.js`: 선택적 MediaRecorder 녹화 및 종료 처리
- `js/ui/setup.js`, `practice.js`, `report.js`: 질문 설정, 답변, 재생·메모·비교
- `js/sensors/`: 로컬 카메라·마이크 및 데모 센서
- `vendor/`: p5 및 MediaPipe 모델·WASM
- `tests/`: 단위·회귀 테스트

이전 종합 평가·자동 조언·외부 음성 인식 모듈은 제거했습니다. 말하기 속도는 로컬 마이크의 음량 변화로만 추정하며, 복기는 `analysis/review.js`의 관찰 요약을 사용합니다. `docs/superpowers/`는 이전 발표 대시보드 설계 기록이며, 현재 동작은 이 README를 기준으로 합니다.

## 개인별 시선 보정과 확인

1. 준비 확인을 마치면 기본 보정에 고개 각도뿐 아니라 눈별 열림·홍채 위치·눈 방향 신호·얼굴 크기를 기록합니다.
2. 선택 기능인 **정밀 시선 보정**은 실제 기기의 카메라 렌즈, 화면 중앙, 왼쪽·오른쪽·위·아래를 차례로 안내합니다. 이동 직후 표본, 반복 영상 프레임, 눈 감김, 흔들리는 표본은 수집에서 제외합니다. 각 지점에 안정적인 새 표본이 충분해야 다음으로 넘어갑니다.
3. 취소(Esc 포함) 또는 표본·방향 구분 부족 시 이전 보정값을 유지합니다. ‘기본 보정으로’ 버튼으로 정밀 보정을 해제할 수 있습니다.
4. 기본 계산 방식은 눈 방향 blendshape입니다. **홍채 방식은 실험 옵션**이며 자동으로 선택되지 않습니다. 눈 내부 좌표를 눈 너비·기울기·영상 종횡비로 정규화하고 개인 경계와 비교합니다. 정밀 보정 전에는 기본 정면 홍채 기준과 공통 경계를 사용하므로, 점검 화면에서 제한을 확인하세요.
5. 설정 화면의 **시선 인식 테스트**는 보정과 별도의 표본으로 두 방식의 안내 방향 일치·시선 미측정 비율을 나란히 표시합니다. ‘시작→첫 일치’에는 사람의 움직임과 평활화 시간이 포함되며 순수 센서 지연이 아닙니다. 점수·통과 판정 없이 사용자가 계산 방식을 직접 선택합니다. 점검 표본으로 보정값을 다시 학습하지 않습니다.
6. 재연습 때 저장된 정밀 보정은 새 기본 렌즈 표본의 고개 각도·얼굴 크기·홍채 기준이 유사할 때만 유지합니다. 정밀 보정은 현재 탭에만 남고 영구 저장하지 않습니다.

**제외·불확실 처리:** 양쪽 눈 감김, 눈 검출 불안정, 영상 정지, 작은 눈 영상, 보정 범위 밖, 고개·눈의 반대 방향 신호를 표시합니다. 한쪽 눈만 사용 가능하면 그 눈을 표시합니다. 손 가림·반사·눈 감김 여부는 영상 기반 추정으로 완벽하게 구분되지 않을 수 있습니다.

**시간 집계:** 새 시선 관찰은 원시값·안정화값·두 방식의 결과·눈별 상태와 함께 기록합니다. 각 관찰을 다음 관찰까지 최대 0.15초만 유지해 시간으로 집계하며, 더 긴 공백은 미측정 시간입니다. 10Hz 화면 갱신 횟수를 시선 측정 횟수로 세지 않습니다. 고개가 명확히 정면 범위 밖인 경우에는 눈 상태가 불확실해도 고개 관찰을 기록할 수 있습니다.

복기 화면의 시선·고개·눈 띠에서 구간을 선택해 녹화와 대조하고, 측정값 JSON으로 원시·안정화·보정값을 함께 내려받을 수 있습니다. 두 방식의 방향 일치는 실제 응시 정확도나 면접 역량을 뜻하지 않습니다. 정확한 화면 좌표와 응시 히트맵은 제공하지 않습니다.

추가 검증:

```sh
npm run setup:browser
npm run test:browser:gaze
```

서버는 자동 시작·종료됩니다. 스크립트는 가상 눈 표본을 사용하며 실제 카메라·마이크 접근을 차단합니다. 실제 사용자·웹캠 환경에서의 인식 정확도 검증과는 구분됩니다.
